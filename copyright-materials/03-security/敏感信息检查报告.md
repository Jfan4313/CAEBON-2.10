# 敏感信息检查报告

检查日期：2026-08-02

## 检查范围与方法

对 Git 跟踪文件及申报材料目录检查常见 API 密钥、JWT、云服务地址、私钥头、个人绝对路径、环境变量文件、客户名称和输出文件。检查过程仅记录变量名与文件位置，不在报告中复制秘密值。

## 结果

- 未发现 `sk-` 类密钥、AWS Access Key、JWT、RSA/EC/OpenSSH 私钥内容。
- `.env` 与 `.env.development` 当前被 Git 跟踪，这是版本管理风险；即使现有内容未检出典型密钥，也必须从正式源码归档中排除，并在冻结提交前停止跟踪而保留本地文件。
- `.env.example` 含 Supabase 示例地址和变量占位符，不含已识别真实密钥；可保留在研发仓库，但不需要进入软著自主源程序。
- `fix_divs.py`、`fix_project_entry.js`、`test.py`、`test_rc.py`、`track_divs.py` 含历史个人绝对路径，应从正式归档排除。
- `outputs/` 包含历史 Excel、预览图和构建脚本，`tmp/` 为临时目录，均已加入忽略和归档排除规则。
- `SUPABASE_SETUP.md` 与 SQL 脚本属于可选云服务配置，不进入 V2.14 自主源程序鉴别材料。

## 申报目录结论

当前 `copyright-materials/` 新生成内容使用匿名“广东工业园标准项目”，不包含真实客户名称、账号、账单、个人地址或密钥。最终打包前仍需再次执行同一规则扫描，并确认权属文件中用户后来填写的身份证明按登记要求单独管理，不混入公开技术归档。
